## ① 多言語化(i18n)フェーズの進捗

### 基盤：完成済み

`src/i18n/i18n.js`（540行・v1.0.0）に以下が実装済み。

- **ネイティブライブラリ不使用**（＝Dev Build のリビルド不要という設計判断）
- **React Context** で言語を全画面共有 → トグルで即時反映
- **AsyncStorage**（キー `settings_lang`）に選択言語を保存 → 再起動しても復元
- `App.js` 全体を `<LanguageProvider>` で包む構成（v3.1.0で対応済み）

**辞書は2タイプ構成：**

| タイプ | 形式 | 用途 |
|---|---|---|
| タイプA（文字列） | `key → { ja: "文字列", en: "string" }` | 固定文言 |
| タイプB（関数） | `key → { ja: (args)=>\`...\`, en: (args)=>\`...\` }` | 変数が混じる文言（チェーン名・件数・年月など） |

**`t()` の安全設計：**
- 辞書の中身が関数なら実行、文字列ならそのまま返す（型判定）
- キーが存在しなければ**キー名をそのまま返す**（フォールバック＝クラッシュ防止）

**公開API（`src/i18n/i18n.js`）：**
```js
export function LanguageProvider({ children })  // L489
export function useI18n()                        // L538
```

> ⚠️ **フックの名前は `useI18n` です。`useLang` ではありません。** 新規画面を対応させるときは `import { useI18n } from '../i18n/i18n';` と書くこと。

## ③ 構文チェックの正しい方法

### ❌ やってはいけない

```bash
node --input-type=module -e "..."   # JSXを構文エラーとして検出できない／見逃す
```

Node単体は JSX を解釈できないため、**JSXの構文ミスをすり抜けます**。
「チェックが通ったのに実機で落ちる」の原因になるので使わないこと。

### ✅ 正しい方法 A：esbuild（推奨・一発で済む）

```bash
npx --yes esbuild --loader=jsx --log-level=warning --outfile=/dev/null src/screens/RecordDetail.js
```

全画面を一括チェック：
```bash
for f in src/screens/*.js src/services/*.js src/i18n/*.js App.js; do
  npx --yes esbuild --loader=jsx --log-level=warning --outfile=/dev/null "$f" || echo "❌ $f"
done
```

### ✅ 正しい方法 B：@babel/core + @babel/preset-react

```bash
npm i -D @babel/core @babel/preset-react
```

```bash
node -e "
const babel = require('@babel/core');
const fs = require('fs');
const file = process.argv[1];
try {
  babel.transformSync(fs.readFileSync(file, 'utf8'), {
    filename: file,
    presets: [['@babel/preset-react', { runtime: 'automatic' }]],
  });
  console.log('✅ OK:', file);
} catch (e) {
  console.error('❌ NG:', file, '\n', e.message);
  process.exit(1);
}
" src/screens/RecordDetail.js
```

**ポイント：実際にコンパイルを通すこと。** パースだけ・目視だけでは JSX の閉じ忘れや
タグの対応ミスを検出できません。

## ⚡ エナジー（EN）仕様

- 1EN = 5分のムーブ時間
- 世界共通で1日4回補充（UTC 1:00 / 7:00 / 13:00 / 19:00）
- 最大EN：靴の保有数と質で決まる（1チェーン最大20EN、3チェーン合計最大60EN）
- ENが0の状態ではトークン獲得不可
- マーケット出品中の靴はEN計算から除外される

| 保有数(Common) | EN上限 |
|--------|--------|
| 1足 | 2 |
| 3足 | 4 |
| 9足 | 9 |
| 15足 | 12 |
| 30足 | 20 |

## 🚨 設計上の注意事項（v3から継続）

1. **チェーン選択は取込前に必須**：取込後の変更は修正履歴に記録
2. **marketplace_listing → sell の昇格**：ユーザーの手動操作が必要
3. **repair_hp と repair_durability は別レコード**：同日に両方発生する場合あり
4. **spending_withdraw の手数料GST**：本体の送金額とは別に支出として記録
5. **spending_deposit の手数料SOL/BNB/POL**：Spending残高には影響しないが記録推奨
6. **Spending残高の照合ロジック**：初期残高 + 収入合計 - 支出合計 = 計算残高
7. **画像は取込確認後に破棄**：詳細画面での修正は手入力で対応
8. **月別データ分割**：`records_index`で管理、またがった集計も対応
