# STEPN 収支管理ツール 設計メモ

## 目的
STEPNのムーブ記録・支出・収入を
スクショ画像から自動解析して記録・管理する

## 取り込み対象画面
- ホーム画面（GST/GMT残高・エナジー）
- ムーブ結果画面（獲得量・距離・時間）
- リペア画面（消費GST・耐久度）
- ミント画面（予定）
- マーケット売買画面（予定）

## 設計上の注意点
- チェーン判別：ムーブ記録画面にはチェーン
  シンボルが映らないため要検討
  → 手動選択 or ホーム画面とセットで取込み
- MBレアリティ：Lv.1〜10の10種類をDB化必要
- GSTとGMTは同時アーン不可（モード切替制）
- GMTアーンはLv.30以上の靴のみ

## 使用技術（予定）
- Claude Vision API（画像解析）
- React Native / Expo（アプリ）
- AsyncStorage（ローカル保存）
- CSV出力（確定申告用）

## 📌 確定済み重要仕様

### 1. ホーム画面のインジケーターバー仕様（超重要）

STARTボタン右のトグルスイッチで2種類のバーが切り替わる：

| トグル状態 | アイコン | バーの意味 |
|------------|----------|------------|
| GSTモード（グレー表示） | 靴マーク | GST デイリーキャップ進捗（例：924.56/1000） |
| GMTモード（ゴールド表示） | Gマーク（丸の中にG） | GMT トータル累計獲得量（例：107840.7、上限なしのためスラッシュなし） |

**Visionプロンプトの判定ロジック：**
① トグルの色・テキストを先に読む（STEP 1）
② バーの解釈を分岐させる（STEP 2）

`home` フィールド：
- `earn_mode: "GST" | "GMT"`
- `gst_daily_earned: number | null`（GSTモード時）
- `gst_daily_cap: number | null`（GSTモード時）
- `gmt_total_earned: number | null`（GMTモード時）

### 2. VIPサービス仕様

**MEMBERSHIPスクリーンの特典3種：**
- Special VIP Profile Tag
- Keep a Minting Scroll after minting（2%）
- Keep a Gem after unsuccessful upgrade（3%）

**重要：VIPサブスクは法定通貨（iTunes/Google Play課金）**
→ 確定申告上、GST/GMTとは**別の支出カテゴリ**として管理必須！

### 3. VIPバナー検出（重要）

| バナー文字列 | 意味 | 該当カテゴリ・フィールド |
|---|---|---|
| `"You kept 1 Gem"` | VIP 3%特典発動 | `gem_upgrade_fail.vip_kept_gem` |
| `"You kept 1 Minting Scroll"` | VIP 2%特典発動 | `shoe_mint_result.vip_kept_scroll` |

→ **これらのバナー文字列をプロンプトに明示的に記載済み**

### 4. チェーン判定方式

- ムーブ結果画面にはチェーンシンボルが映らない
- **手動UI選択方式で確定済み**

### 5. ミントコスト仕様

- コストは親靴2足それぞれの**レアリティ × ミント回数（0〜7）**の組み合わせで変動
- 実測値（3380 GST / 820 GMT）はプロンプト内で**サニティチェック用ヒント**として使用
- Vision APIは常にスクショの数字を優先して読む設計

### 6. ウォレット仕様

| ウォレット種別 | 用途 |
|---|---|
| Spending Wallet | インゲームアクション（リペア・アップグレード等） |
| Holding Wallet | マーケット・外部送金 |

## 🚨 Visionプロンプト設計上のトラップ（注意事項）

1. **ホームバートグル問題：** バー数値を読む前にトグル色を先に判定すること（STEP 1 → STEP 2の2段階）
2. **VIPバナー検出：** "You kept 1 Gem" / "You kept 1 Minting Scroll" の文字列を明示的にプロンプトに記載
3. **VIPスクショは発動時のみ：** バナーが出ない場合はfalseが正常
4. **チェーン判定：** ムーブ結果画面はチェーンシンボルなし → 手動UI選択で確定
5. **Comfort属性値：** 靴詳細の +120 等の表記（ホームのインジケーターバーとは無関係）
6. **ミントコスト：** 実測値はサニティチェック用のみ、常にスクショの値を優先
7. **wallet_transfer：** Spending↔Holding間の内部移動は"external"にしない
8. **shoe_mint_cost と shoe_mint_result：** ペアで管理する設計（ミント前後）
9. **marketplace_sell：** "listed"（出品中）と"sold"（売却完了）を sale_status で区別

## 📌 全カテゴリ共通ルール

### timestamp ルール
```
全カテゴリ共通：取込時刻（created_at）を timestamp に使用する
OCR画像内の時刻（ステータスバー）は機種・設定依存のため使用しない
数日後にまとめて取り込む場合もあるため
```

### 靴ID ルール（絶対に間違えないこと）
```
"#XXXXXXXXX" → 通常の靴のID
"GXXXXXXXXX" → Genesis靴のID（先頭Gはゲネシスの証）
両方とも靴のIDであることに変わりない
"G" prefix を「GSTトークン」と混同しないこと
```

### チェーン ルール
```
チェーン情報はOCRテキストから読まない
ホーム画面で手動選択されたチェーンを analyze(ocrText, chain) の引数で受け取る
```

### トークン金額の保存ルール
```
gst_amount / gmt_amount は常に正数で保存（符号なし）
収支の方向は type フィールド（income / expense）で管理する
```

### 靴レアリティ判定ルール
```
OCRのテキストではレアリティは読めない
靴カードのインジケーターバーのピクセル色で判定する（B案確定）
STEPNアプリのUIは4年以上変更なし → 座標ベース判定が有効
色対応表：
  Common    → グレー  (150, 150, 150)
  Uncommon  → 緑     (  0, 200, 100)
  Rare      → 青     ( 50, 100, 255)
  Epic      → 紫     (150,  50, 255)
  Legendary → 金     (255, 200,   0)
```

## ✅ 確定済みカテゴリ定義

---

### 1. `move_result`（収入系）
**確定日：2026/05/08**

#### カテゴリ判定キーワード
```
"GST/Min" または "GMT/Min" がOCRテキストに含まれる → 確定
```

#### 必須フィールド
| フィールド | 取り方 | 備考 |
|-----------|--------|------|
| `earn_mode` | `GST/Min` → "GST" \| `GMT/Min` → "GMT" | アーンモード |
| `earn_amount` | `+` の直後の数値（最後の数値を取る） | GMT版は "5 + 151.51" のようにノイズが混入するため末尾数値を取得 |

#### optionalフィールド（extra に格納）
| フィールド | 取り方 | 備考 |
|-----------|--------|------|
| `move_date` | `DD/MM/YYYY HH:MM` パターン | extraに保存（timestampには使わない） |
| `duration` | `HH:MM:SS` パターン | ムーブ実働時間 |
| `steps` | `Steps` ラベル直前の数値 | 歩数 |
| `distance_km` | `Km` ラベル直前の数値 | 走行距離 |
| `en_used` | `- X.X` パターンの数値（正数で保存） | EN消費量 |
| `mb_obtained` | `Your slots are full` が**ない** → true | MB取得フラグ |
| `mb_level` | `mb_obtained=true` のときユーザー手動入力（1〜10） | MBレベル |
| `mb_quality` | `mb_level` からテーブル変換 | MB品質名 |

#### MBレベル → 品質変換テーブル
```
1: Damaged      2: Refurbished
3: Common       4: Uncommon
5: Rare         6: Epic
7: Legendary    8: Enchanted
9: Master       10: Satoshi
```

#### MBアイコン判定ルール
```
OCRではMBレベルのアイコン画像を判定不可（同系色ペアが複数あるため）
→ mb_obtained=true のとき確認画面でユーザーが手動選択（C案確定）

アイコン色の同系色問題：
  Lv1グレー ≒ Lv2グレー
  Lv3緑    ≒ Lv4緑
  Lv5青    ≒ Lv6青（薄）
  Lv7紫    ≒ Lv8紫（薄）
```

#### `Your slots are full` の判定ロジック
```
あり  → mb_obtained = false（スロット満杯でMB拾えなかった）
なし  → mb_obtained = true （MBを取得した）
※ フラグ判定後は読み捨て（ignoreに含める）
```

#### 無視するOCRテキスト（ノイズ）
```
固定文字列：
  "STEPNA" "STEP'N"          ← ロゴの誤認識
  "Long press to identify and download APP"  ← 広告
  "END" "GO"                 ← マップマーカー
  "Human"                    ← 認証バッジ
  "Steps"                    ← ラベル（数値は取る）
  "Time"                     ← ラベル（数値は取る）
  "Km"                       ← ラベル（数値は取る）
  "x 1" "x1"                 ← MB個数（slots full で代替）
  "Your slots are full"      ← フラグ判定後に読み捨て

正規表現：
  /^[iG]\s/      → "i Jogger" "i Walker" 等のアイコン誤認識
  /^[Ii][Ii]\s*\d+/  → "ll 4G" "II 964" 等のジェムアイコン誤認識
  /^#\s*\d+/     → 靴ID（#XXXXXXXXX）
  /^G\d+/        → Genesis靴ID
  /^\d{3,5}$/    → 歩数（3〜5桁の数字のみの行）
```

### 2. `level_up`（支出系）
**確定日：2026/05/08**

#### カテゴリ判定キーワード
```
"LEVEL UP" がOCRテキストに含まれる
ただし "LEVEL UP SUCCESS" "LEVEL UP FAILED" はジェムUPなので除外
→ "LEVEL UP" AND NOT ("SUCCESS" OR "FAILED") で確定
```

#### 必須フィールド
| フィールド | 取り方 | 備考 |

| `level_after` | `Level up to LvX` の数値X | アップ後のレベル |

| `gmt_cost` | `X GMT` の数値（なければ0） | GMT消費量 |

#### コストの3パターン
```
GSTのみ  ："3 GST"          → gst_cost:3,     gmt_cost:0
GST+GMT ："10 GST+ 10 GMT" → gst_cost:10,    gmt_cost:10
GMTのみ  ："25000 GMT"      → gst_cost:0,     gmt_cost:25000
```

| `wait_mins` | `XXX mins` の数値 | 待機時間（収支に不要・参考記録） |

#### 無視するOCRテキスト（ノイズ）
```
固定文字列：
  "Cost" "Time" "CANCEL" "CONFIRM"
  "Efficiency" "Etticiency" "Erticiency"  ← 誤認識バリエーション
  "Luck" "U Luck"
  "Comfort" "Resilience"
  "Repair" "Mint"
  "Sell" "Fusion" "Transfer"

正規表現：
  /^\d{4,}\.?\d*$/   → 残高（4桁以上の数値）
  /^[Ii][Ii]\s*\d+/  → "ll 964" 等のアイコン誤認識
```


### 2. 全カテゴリ共通ルール

```
【timestamp】
全カテゴリ共通：取込時刻（created_at）を timestamp に使用する
OCR画像内の時刻（ステータスバー）は機種・設定依存のため使用しない

【チェーン】
チェーン情報はOCRテキストから読まない
analyze(ocrText, chain) の引数で受け取る（手動UI選択方式で確定）

【トークン金額】
gst_amount / gmt_amount は常に正数で保存（符号なし）
収支の方向は type フィールドで管理

【靴レアリティ判定】
OCRのテキストでは読めない
靴カードのインジケーターバーのピクセル色で判定（B案確定）

  Uncommon  → 緑     (0,200,100)
  Rare      → 青     (50,100,255)
  Epic      → 紫     (150,50,255)
  Legendary → 金     (255,200,0)

【ジェムLv・絶対に混同しないこと】
```

### 1. FNV-1aハッシュ（重複検出）
```javascript
// expo-crypto を使わず純JSで実装
const fnv1aHash = (str) => {
  let h = 2166136261;
  for (let i = 0; i < str.length; i++) {
    h ^= str.charCodeAt(i);
    h = (h * 16777619) >>> 0;
  }
  return h.toString(16).padStart(8, '0');
};
// 先頭5KB+末尾5KBでハッシュ（衝突回避）
imageHash = fnv1aHash(base64.slice(0, 5000) + base64.slice(-5000));
```

### 4. ピクセル解析（VisionAnalyzer_pixel.js）v3.4.x

**チェーン判定（_classifyChainColor）：**
```javascript
// オーバーレイ越しの実測値に基づく判定（絶対値ではなく色パターンで判定）
BNB: r > g && g > b && r - b > 12 && sat > 8   // 実測: RGB(81,78,63)
POL: b > g && r > g && sat > 10                  // 実測: RGB(51,39,73)
SOL: それ以外（グレー系）                          // 実測: RGB(72,83,79)
// クロップ座標: x=68-96%, y=3-11%（4x1リサイズ）
```

**MB結果検出（detectMbResultByPixel）：**
```javascript
// 12ポイントサンプリング: y=62%,68%,74% × x=15%,38%,62%,85%
// 輝度(bri)>160 が3点以上 → mb_result
// ホーム画面はSTARTボタン（暗緑）+暗い背景 → bri低い → home
```

**ジェムLv判定（_classifyGemLevel）：**
```javascript
// 上部・下部の輝度差で判定
diff = briL - briU
if (diff > 30) → Lv1（三角：下部が白背景）
// Lv2/3の区別は中央部彩度（midSat）で判定
if (midSat > 40) → Lv3（大ダイヤ）
else → Lv2（小ダイヤ）
// ただし、MBの仕様上「左から順にLv1/2/3固定」なので実際はgem_level自動割り当て
```

**MBスロット色判定（_classifyMbSlot）：**
```javascript
// 現状の精度: slot 0（左端）は安定 / slot 1,2 はグロー影響で不安定
// → 取込確認画面でユーザーが色を手動選択（ハイブリッド方式）
efficiency: r > g && g > b && r - b > 30  // 黄/金色
comfort:    r > b && r >= g && sat > 5    // 赤/オレンジ
resilience: b > g && b > r && b - g > 8  // 紫
luck:       g > r && b > r               // 水色
scroll:     sat <= 8                     // グレー（ミンスク）
```
